# Как бот справляется в каждом сегменте

Сравниваю обращения после 1 апреля в письменных каналах (там работает бот) с теми же сегментами до апреля, когда отвечали только люди. Телефон, где бота нет, нужен как контроль.

Запуск из корня репозитория: `python3 src/run_sql.py analysis/03_bot_by_segment.md`

### 1. Доля обращений, закрытых ботом

**Итог:** после 1 апреля в письменных каналах бот сам закрыл в первой линии 74,8% обращений (1217 из 1626), в серой зоне 51,8% (285 из 550), во второй линии 32,2% (165 из 512).

Чем сложнее сегмент, тем реже бот закрывает обращение сам и тем чаще передаёт человеку: из второй линии он передал 347 из 512.

```sql
SELECT segment, COUNT(*), SUM(bot_result = 'закрыл'), ROUND(AVG(bot_result = 'закрыл') * 100, 1)
FROM segmented
WHERE period = 'после' AND written = 1
GROUP BY segment;
```

### 2. Решено с первого раза: по флагу переоткрытия

**Итог:** доля обращений без переоткрытия (люди до апреля / все после апреля / только закрытые ботом): первая линия 94,5% / 95,5% / 96,3%, серая зона 90,2% / 89,3% / 93,0%, вторая линия 84,0% / 83,6% / 80,6%.

По этому определению бот выглядит не хуже людей: в первой линии и в серой зоне даже лучше, а во второй линии отставание всего 3,4 пункта (84,0 против 80,6).

```sql
-- люди до апреля (письменные каналы)
SELECT segment, COUNT(*), ROUND(AVG(reopened = 0) * 100, 1)
FROM segmented WHERE period = 'до' AND written = 1 GROUP BY segment;
-- все обращения после апреля
SELECT segment, COUNT(*), ROUND(AVG(reopened = 0) * 100, 1)
FROM segmented WHERE period = 'после' AND written = 1 GROUP BY segment;
-- только закрытые ботом
SELECT segment, COUNT(*), ROUND(AVG(reopened = 0) * 100, 1)
FROM segmented WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл' GROUP BY segment;
```

### 3. Решено с первого раза: с учётом возвратов

**Итог:** доля обращений без переоткрытия и без возврата (люди до апреля / все после апреля / только закрытые ботом): первая линия 89,3% / 87,5% / 87,8%, серая зона 83,2% / 78,0% / 78,6%, вторая линия 76,8% / 69,1% / 47,9%.

Для вывода берётся определение с возвратами. Флаг `reopened` видит только клиента, который открыл то же обращение заново. Клиента, который не получил помощи и написал новое обращение с той же темой, он не видит: поэтому во второй линии флаг показывает у бота 80,6%, а с возвратами остаётся 47,9%, то есть разница 32,7 пункта скрыта именно там, где она больше всего. У определения с возвратами тоже есть слепые места: для обращений без темы (`без темы`, `NULL`) возврат равен 0 по построению, а у обращений последней недели июня семидневное окно возврата упирается в конец выгрузки (`01_data_audit.md`, п. 9 и вывод 3), поэтому возвратов там недосчитано. Оба смещения лежат в сторону завышения «решено», то есть число 47,9% скорее оптимистично для бота.

```sql
-- люди до апреля (письменные каналы)
SELECT segment, COUNT(*), ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE period = 'до' AND written = 1 GROUP BY segment;
-- все обращения после апреля
SELECT segment, COUNT(*), ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE period = 'после' AND written = 1 GROUP BY segment;
-- только закрытые ботом
SELECT segment, COUNT(*), ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл' GROUP BY segment;
```

### 4. Контроль: телефон

**Итог:** по телефону, где бота нет, доля «решено без переоткрытия и возврата» упала с 84,5% до 82,9% (на 1,6 пункта), а в письменных каналах с 85,7% до 82,0% (на 3,7 пункта); часть падения происходит не из-за бота.

Контроль нужен, чтобы отделить влияние бота от всего остального, что поменялось между периодами: сезон, нагрузка, конец выгрузки (у обращений июня возврат ещё не успел произойти). Телефон проходит через те же месяцы и ту же выгрузку, но без бота, поэтому любое изменение, которое видно и там, нельзя приписывать боту. Бот объясняет только разницу между падением в письменных каналах и на телефоне: около 2 пунктов, а не все 3,7.

```sql
SELECT period, COUNT(*), ROUND(AVG(reopened = 0) * 100, 1), ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE written = 0 GROUP BY period;      -- телефон до и после
SELECT period, COUNT(*), ROUND(AVG(reopened = 0) * 100, 1), ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE written = 1 GROUP BY period;      -- письменные каналы до и после
```

### 5. Два варианта границы серой зоны

**Итог:** если серую зону отнести ко второй линии, то люди до апреля решали с первого раза 80,2%, бот закрывает 42,4%, а среди закрытых ботом решено 67,3%; если серую зону отнести к первой линии, то 76,8%, 32,2% и 47,9%. Решено везде считается как «без переоткрытия и без возврата».

| Сценарий | Люди до апреля | Доля закрытых ботом | Решено среди закрытых ботом |
|---|---|---|---|
| серая → вторая | 80,2% | 42,4% | 67,3% |
| серая → первая | 76,8% | 32,2% | 47,9% |

Серая зона делает провал бота на второй линии незаметным: разрыв с людьми в сценарии «серая → вторая» 12,9 пункта (80,2 против 67,3), а на чисто второй линии 28,9 пункта (76,8 против 47,9). От определения серой зоны зависит, насколько выгодно выглядит бот.

```sql
-- сценарий: серая зона относится ко второй линии
SELECT ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE period = 'до' AND written = 1 AND segment IN ('вторая', 'серая');   -- люди до апреля
SELECT ROUND(AVG(bot_result = 'закрыл') * 100, 1)
FROM segmented WHERE period = 'после' AND written = 1 AND segment IN ('вторая', 'серая');   -- доля закрытых ботом
SELECT ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл'
  AND segment IN ('вторая', 'серая');                                                    -- решено среди закрытых ботом
-- сценарий: серая зона относится к первой линии
SELECT ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE period = 'до' AND written = 1 AND segment = 'вторая';
SELECT ROUND(AVG(bot_result = 'закрыл') * 100, 1)
FROM segmented WHERE period = 'после' AND written = 1 AND segment = 'вторая';
SELECT ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1)
FROM segmented WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл' AND segment = 'вторая';
```

### 6. Что происходит с клиентом после бота

**Итог:** бот закрыл 165 обращений второй линии, клиент вернулся в течение 7 дней в 56 случаях (33,9%); из этих 56 возвратов бот снова закрыл 7, передал человеку 20, а в 29 случаях бота не было вовсе.

После апреля `next_bot_result = 'нет'` бывает только у телефона, то есть 29 из 56 клиентов после бота позвонили. Значит, 49 из 56 возвращавшихся (87,5%) в итоге попали к человеку, и только 7 получили повторное закрытие от бота. Всего не решено 86 из 165 закрытых ботом обращений второй линии (32 переоткрыты, 56 с возвратом). Если считать вместе с серой зоной: закрыто 450, возвратов 97 (21,6%), из них бот снова закрыл 19, передал 33, звонков 45.

```sql
-- только вторая линия
SELECT COUNT(*), SUM(came_back),
       SUM(came_back = 1 AND next_bot_result = 'закрыл'),
       SUM(came_back = 1 AND next_bot_result = 'передал'),
       SUM(came_back = 1 AND next_bot_result = 'нет')
FROM segmented WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл' AND segment = 'вторая';
-- вместе с серой зоной
SELECT COUNT(*), SUM(came_back),
       SUM(came_back = 1 AND next_bot_result = 'закрыл'),
       SUM(came_back = 1 AND next_bot_result = 'передал'),
       SUM(came_back = 1 AND next_bot_result = 'нет')
FROM segmented WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл'
  AND segment IN ('вторая', 'серая');
-- после апреля бота нет только у телефона
SELECT channel, bot_result, COUNT(*) FROM segmented
WHERE period = 'после' AND bot_result = 'нет' GROUP BY channel, bot_result;
-- сколько из закрытых ботом обращений второй линии не решено
SELECT COUNT(*), SUM(NOT (reopened = 0 AND came_back = 0))
FROM segmented WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл' AND segment = 'вторая';
```

## Вывод

**Бот — для первой линии, на второй — люди: из обращений второй линии, которые бот закрыл сам, без переоткрытия и возврата решено лишь 47,9% против 76,8% у людей до апреля, то есть 86 из 165 остались нерешёнными.**

Что теряется при таком выводе: в серой зоне бот закрыл 285 обращений почти так же хорошо, как люди (78,6% против 83,2%), это около 119 часов человеческой работы за три месяца (медиана 25 минут на обращение до апреля). Этот вывод отказывается от этой экономии. Если серую зону отнести ко второй линии, разрыв сокращается до 67,3% против 80,2%, и обратный вывод (бот справляется и со второй линией) защищать проще: всё зависит от того, где проведена граница серой зоны.

```sql
-- сколько человеческой работы бот сэкономил в серой зоне (оценка по медиане до апреля)
SELECT (SELECT MEDIAN(handle_min) FROM segmented WHERE period = 'до' AND written = 1 AND segment = 'серая'),
       COUNT(*),
       ROUND(COUNT(*) * (SELECT MEDIAN(handle_min) FROM segmented
                         WHERE period = 'до' AND written = 1 AND segment = 'серая') / 60.0, 0)
FROM segmented WHERE period = 'после' AND written = 1 AND segment = 'серая' AND bot_result = 'закрыл';
```
