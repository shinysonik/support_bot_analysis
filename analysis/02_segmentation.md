# Сегментация обращений

Смотрю на данные до 1 апреля, когда все обращения разбирали люди, и делю обращения на три сегмента: первая линия, серая зона, вторая линия. Решение по каждой паре «тема + приоритет» лежит в `analysis/segments.csv`, база подхватывает его сама.

Запуск из корня репозитория: `python3 src/run_sql.py analysis/02_segmentation.md`

### 1. Время обработки по темам до апреля

**Итог:** медиана времени обработки до апреля (по всем темам 16 мин): быстрые темы — доступ и пароли 7 мин, расписание и посещаемость 8; средние — без темы 15,5, NULL 16, прочее 17, оплата и документы 19, техническая проблема 22; долгие — жалоба 53, возврат денег 54, юридический вопрос 59.

Темы делятся на три группы с разрывами между ними: 7–8, 15–22 и 53–59 минут. Среднее везде выше медианы (например, 70,0 против 59 у юридического вопроса): долгие обращения тянут среднее вверх, поэтому сегментация опирается на медиану.

```sql
SELECT topic, COUNT(*), MEDIAN(handle_min), ROUND(AVG(handle_min), 1)
FROM clean WHERE period = 'до' GROUP BY topic ORDER BY 3;
SELECT MEDIAN(handle_min) FROM clean WHERE period = 'до';   -- по всем темам вместе
```

### 2. Время обработки по теме и приоритету до апреля

**Итог:** в средних темах приоритет 1 дольше приоритета 3 (оплата и документы 30 / 19 / 11 мин для приоритетов 1 / 2 / 3, техническая проблема 33 / 20 / 16, прочее 29 / 16 / 10); у доступа и расписания приоритет почти не влияет (7–9 мин), а у возврата денег, жалобы и юридического вопроса даже приоритет 3 даёт от 40 мин.

Поэтому для средних тем граница проведена внутри темы по приоритету, а для быстрых и долгих тем целиком. Две строки лежат рядом с границей 40 минут: возврат денег с приоритетом 3 (40,5) и жалоба с приоритетом 3 (41,5). Они отнесены ко второй линии, потому что остальные приоритеты этих тем дают 46–71 мин и вся тема долгая.

```sql
SELECT topic, priority, COUNT(*), MEDIAN(handle_min)
FROM clean WHERE period = 'до' GROUP BY topic, priority ORDER BY topic, priority;
SELECT priority, COUNT(*), MEDIAN(handle_min)
FROM clean WHERE period = 'до' GROUP BY priority;           -- приоритет сам по себе: 39 / 15 / 9
```

### 3. Возвраты и переоткрытия по темам до апреля

**Итог:** чаще всего переоткрывают возврат денег (18,5%) и жалобы (16,0%), реже всего доступ и пароли (3,1%) и расписание (4,2%), в среднем 8,5%; возвраты чаще всего у технической проблемы и жалобы (по 9,2%), в среднем 6,2%.

Для тем `без темы` и `NULL` возврат равен 0 по построению (тема неизвестна, поэтому «ту же тему» найти нельзя), и их по возвратам сравнивать нельзя. Долгие темы (возврат денег, жалоба) и переоткрываются чаще всего: это ещё один признак, что обращения сложные и не закрываются с первого раза.

```sql
SELECT topic, COUNT(*), ROUND(AVG(reopened) * 100, 1), ROUND(AVG(came_back) * 100, 1)
FROM clean WHERE period = 'до' GROUP BY topic ORDER BY 3 DESC;
SELECT ROUND(AVG(reopened) * 100, 1), ROUND(AVG(came_back) * 100, 1)
FROM clean WHERE period = 'до';                              -- в среднем 8,5 и 6,2
```

### 4. Размер сегментов

**Итог:** до апреля первая линия 1901 обращение, серая зона 676, вторая линия 634; после апреля первая 2075, серая 726, вторая 748; неразмеченных нет (0).

Границы сегментов подтверждаются данными до апреля: медиана времени обработки у первой линии 9 мин, у серой зоны 26 мин, у второй 55 мин; переоткрывают 5,4%, 10,8% и 15,5% обращений соответственно.

```sql
SELECT period, segment, COUNT(*) FROM segmented GROUP BY period, segment ORDER BY period DESC, segment;
SELECT COUNT(*) FROM segmented WHERE segment = 'без сегмента';     -- должно быть 0
SELECT segment, COUNT(*), MEDIAN(handle_min), ROUND(AVG(reopened) * 100, 1)
FROM segmented WHERE period = 'до' GROUP BY segment;               -- чем сегменты отличаются до апреля
```

## Итог

**Во вторую линию попадало бы около 230 обращений в месяц (20,4% всех, 1382 за шесть месяцев), в серую зону около 234 в месяц (20,7%, 1402). Если серую зону тоже отдать второй линии, то около 464 в месяц, или 41,2%.** Разница между 20% и 41% зависит от решения про серую зону, поэтому его нужно называть вместе с числом.

Граница проведена по времени обработки: медиана до апреля меньше 20 минут — первая линия, от 20 до 40 — серая зона, от 40 минут — вторая. Подтверждение из данных до апреля: медиана времени обработки во втором блоке 55 минут, в серой зоне 26, в первом 9; переоткрывают 15,5%, 10,8% и 5,4% обращений. По месяцам вторая линия получает от 193 до 266 обращений и серая зона от 218 до 256, то есть нагрузка устойчива. Числа немного занижены: в нумерации выгрузки не хватает 187 номеров (см. `01_data_audit.md`, п. 6).

```sql
SELECT segment, COUNT(*), ROUND(COUNT(*) / 6.0, 0),
       ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM segmented), 1)
FROM segmented GROUP BY segment;                         -- штуки, штуки в месяц, проценты
SELECT month, segment, COUNT(*) FROM segmented
WHERE segment IN ('вторая', 'серая') GROUP BY month, segment ORDER BY segment, month;   -- по месяцам
SELECT ROUND(COUNT(*) / 6.0, 0), ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM segmented), 1)
FROM segmented WHERE segment IN ('вторая', 'серая');     -- если серую зону отдать второй линии: 464 и 41,2%
```
